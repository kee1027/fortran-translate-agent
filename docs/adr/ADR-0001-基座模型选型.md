# ADR-0001：基座模型选型 —— Qwen2.5-Coder-7B-Instruct

- 状态：已接受（2026-10-19）
- 上下文：实施方案原定 LLaMA 3.1 8B，需结合硬件与任务重新论证

## 决策

基座模型采用 **Qwen2.5-Coder-7B-Instruct**，替代原方案的 LLaMA 3.1 8B。

## 理由

1. **任务匹配**：本项目是代码翻译，代码预训练分布比通用能力更重要。Qwen2.5-Coder 在 7B 档代码基准（HumanEval/MBPP 级别）处于领先，结构化输出遵循更好。
2. **硬件约束（决定性）**：训练/推理环境为 6 卡 RTX 5880 但**共享占用**，单卡实际可用约 12GB。Q4 推理约 5GB 无压力；QLoRA 训练在 12GB 单卡上可行（micro_batch=1 + grad_accum=16）。LLaMA 3.1 8B 在同等约束下并无显存优势，能力反而更弱。
3. **不选更大模型的原因**：14B/30B 即使 Q4 推理也需 9–20GB，共享环境下随时 OOM；且偏离"消费级可复现"的项目定位。
4. **面试叙事**：能答出"代码预训练分布 + 基准对比 + 共享显卡显存约束"三层选型理由。

## 备选记录

- LLaMA 3.1 8B：生态最成熟但代码专精度弱，淘汰。
- Qwen3-8B：通用推理更强，但代码专精度不如 Coder 系列，且 thinking 模式增加推理延迟，淘汰。
- Qwen3-Coder-30B：能力上限高，共享显卡不可行，淘汰。

## 影响

- `configs/agent.yaml` 与 `src/llm/` 的默认模型名指向 Qwen2.5-Coder-7B。
- 训练配置按 7B QLoRA 显存约束设计（见 ADR-0003）。
