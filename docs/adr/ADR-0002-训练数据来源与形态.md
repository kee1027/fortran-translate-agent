# ADR-0002：训练数据来源与形态

- 状态：已接受（2026-09→2026-10-19 定稿）
- 上下文：上一微调项目数据不可复用（原语料为开源 Fortran 语料，无平行标签），需重建数据集

## 决策

训练数据 = **强模型 API 合成平行语料（主力）+ 开源真实语料（补充）**，形态为 **单轮直译 70% + 修复对 30%**，总规模 1000–3000 条。

## 数据来源分工

| 来源 | 占比 | 用途 | 质量控制 |
|---|---|---|---|
| 强模型 API 合成（GPT-4 级 / Kimi / DeepSeek） | ~70% | 定向覆盖语法点：数组运算、DO 循环、子程序接口、格式化 I/O、COMMON 块、文件读写 | **双向编译验证**：Fortran 侧过 gfortran 编译+运行，C++17 侧过 `g++ -std=c++17` 编译+运行，双端输出容差内一致；人工抽检 10–20% |
| Rosetta Code | ~10% | 现成的 Fortran↔C++ 任务对照，高质量平行对 | 量小（数十条），同样过双向验证后入库 |
| netlib / LAPACK / SciFortran 子程序 | ~20% | legacy 数值计算风格，贴合真实翻译场景 | 抽子程序级样本，license 均为 BSD/MIT 类 |

## 训练形态（按职责划分）

- **单轮直译对（70%）**：user: Fortran 源码 → assistant: `{"code": ..., "notes": ...}`。支撑 translate 节点的结构化输出稳定性。
- **修复对（30%）**：错误代码 + gfortran 真实报错 → 修复版本。由脚本按 gfortran 错误码分类故意造错再批量编译生成真实错误信息。支撑 repair 节点——**Agent 闭环收益的关键**。
- **明确放弃**：端到端多轮轨迹 SFT。控制流由 LangGraph 负责，模型只需做好单步动作。

## 红线

- 评测集 50 条从上述来源**留出**，做 n-gram 近重复去重，与训练集绝对隔离。
- 灾难性遗忘对策：混入 10–20% 通用指令样本。

## 影响

- 数据合成脚本与质量过滤脚本纳入 M0.5 里程碑。
- 评测集六类语法点各 ≥5 条（见 ADR-0005）。
