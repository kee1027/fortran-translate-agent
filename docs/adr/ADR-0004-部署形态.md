# ADR-0004：部署形态 —— 合并量化 GGUF 为主

- 状态：已接受（2026-10-19）

## 决策

部署以 **merge_and_unload 合并 → llama.cpp 转 GGUF（Q4_K_M）→ `ollama create` 自定义模型** 为主路线；Ollama Modelfile 挂 adapter 仅作训练期 A/B 对照。

## 理由

1. **稳定性**：Ollama 的 `ADAPTER` 指令对 LoRA 的支持存在版本差异，共享开发机上反复踩坑不划算；合并 GGUF 是单文件产物，行为确定。
2. **交付友好**：单文件 GGUF + Modelfile 两行，README 里一行 `ollama create` 即可复现，面试官可亲手跑。
3. **A/B 仍可行**：微调前 vs 微调后对比只需在 Ollama 中切换两个自定义模型名。

## 量化等级

- 交付默认 Q4_K_M（约 5GB）。
- 消融实验备选项：Q5_K_M / Q8_0，用于排查数值等价容差边界样本是否因量化精度翻车。

## 影响

- `docker-compose.yml` 的 ollama 服务挂载合并后 GGUF。
- CI/评测脚本统一从 Ollama 拉取两个模型（base / finetuned）跑 2×2 矩阵（见 ADR-0005）。
