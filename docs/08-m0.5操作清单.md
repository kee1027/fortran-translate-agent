# 08 · M0.5 操作清单（服务器执行版）

> 依据：`docs/全流程方案-定稿-v1.0.md` + ADR-0001~0005 + `docs/07-handoff-to-server.md` §4。
> 与桌面版清单的差异：**训练路线改为条件化**——快照显示 6×5880 全空闲（单卡 48GB 完整），若训练时仍 ≥40GB 可用则走 bf16 LoRA（04 手册主路线）；被占用到 <24GB 才降级 QLoRA。每步先 STAR 后动手，命令由用户执行。

## 第 0 步 · 环境与路线确认

**[S 背景]** 服务器为 6×RTX 5880 Ada（48GB/卡，共享多用户）；2026-10-19 快照全空闲，但占用随时变化。
**[T 目的]** 确定两件事：训练路线（bf16 LoRA vs QLoRA）、双端编译验证模式（原生 vs Docker）。
**[A 操作]** 请你执行并回填：

```bash
nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv   # 精确到卡，不看摘要
which gfortran g++ docker && gfortran --version | head -1 && g++ --version | head -1
```

**[R 结论]**

| 可用显存（单卡） | 训练路线 | 配置文件 |
|---|---|---|
| ≥ 40GB | **bf16 LoRA**（首选，04 手册主路线） | `configs/train_lora_7b.yaml` |
| 24–40GB | bf16 LoRA，micro_batch=1 | 同上，改 `per_device_train_batch_size: 1` |
| < 24GB | **QLoRA** | `configs/train_lora_7b_qlora.yaml`（见第 5 节改动点） |

编译工具链：有 gfortran/g++ → 原生模式；否则 `docker pull gcc:13` 后所有验证命令加 `--docker`。

## 第 1 步 · 数据合成（设计 + 示例）

**[S 背景]** ADR-0002：主力数据靠强模型 API 合成，直译对 70%。数据规范要求每条样本可编译、可运行、可验证。
**[T 目的]** 产出 `data/raw/synthetic/*.json`（未经双端验证的原始合成结果）。验收：`python scripts/validate_dataset.py data/raw/synthetic/某条.json` 通过 schema 校验。

### 设计思路

合成按**语法点矩阵定向造数**（不是随机生成），保证六类语法点均衡覆盖，与评测集（ADR-0005）分布对齐：

```
语法点矩阵（每格 easy/medium/hard 三档）
├── 数组运算    array-section / where / implied-do
├── 循环控制    do-loop / do-while / cycle-exit / nested
├── 子程序      subroutine / function / intent / interface
├── I/O         format(F12.6等) / read-write / file-open
├── 数据共享    common-block / module / save
└── 数值计算    matmul / intrinsic(sin/sqrt) / 精度混合
```

每条样本一次 API 调用完成（源码+测试+说明同源生成），天然满足数据规范字段。

### 示例：`scripts/synthesize_dataset.py`

```python
"""
synthesize_dataset.py — 强模型 API 定向合成 Fortran→C++17 平行样本

设计要点：
1. 按"语法点矩阵"逐格生成 —— 训练分布与 ADR-0005 评测集六类语法点对齐。
2. 一条样本一次 API 调用 —— 源码+测试+说明同源生成，避免多次调用的一致性问题。
3. 不在此脚本里做编译验证 —— 验证是独立质量门（第 2 步），职责分离，
   合成失败和验证失败可分别统计归因。
4. 每条样本记录语法点+难度+index —— 支持定向重试和事后审计"哪一格最难合成"。

用法：
  python scripts/synthesize_dataset.py --cell array/easy --count 5 --seed 42   # 试单格
  python scripts/synthesize_dataset.py --all-cells --count-per-cell 15          # 放量
"""

from __future__ import annotations

import argparse
import json
import os
import time
from pathlib import Path

# 语法点矩阵：整个数据集的"配方"，改数据分布就改这里
SYNTAX_CELLS: dict[str, dict[str, str]] = {
    "array/easy": {
        "topic": "一维数组的声明、初始化和隐式循环(implied-do)输出",
        "fortran_hint": "使用 real(8) 数组、(/ ... /) 构造器、write(*,*) 配合 implied-do",
        "cpp_hint": "用 std::vector<double> 与 range-based for 或 std::ostream_iterator 输出",
    },
    "array/medium": {
        "topic": "二维数组切片与 WHERE 掩码赋值",
        "fortran_hint": "使用 array section (a(:,j))、where 语句",
        "cpp_hint": "手写双重循环实现切片与条件赋值，不使用第三方库",
    },
    "loop/nested": {
        "topic": "嵌套 DO 循环与 CYCLE/EXIT 控制流",
        "fortran_hint": "嵌套 do、cycle、exit，注意循环标签",
        "cpp_hint": "等价的嵌套 for + continue/break",
    },
    "subprogram/subroutine": {
        "topic": "带 intent(in/out/inout) 的 subroutine 参数传递",
        "fortran_hint": "subroutine 修改 intent(inout) 参数",
        "cpp_hint": "用引用参数 void f(double& x) 等价改写",
    },
    "io/format": {
        "topic": "格式化输出 FORMAT(F12.6 等) 的逐位等价",
        "fortran_hint": "write(*,'(F12.6)') 定宽定精度输出",
        "cpp_hint": "用 printf 或 iomanip 精确复现列宽与小数位(Fortran 四舍五入差异要在 notes 里说明)",
    },
    "common-block": {
        "topic": "COMMON 块共享数据",
        "fortran_hint": "common /blk/ a, b 跨子程序共享",
        "cpp_hint": "改为文件作用域 static 或结构体，notes 说明改写策略",
    },
    # 扩充到每格 easy/medium/hard 三档，覆盖 ADR-0005 六类语法点
}

# 输出契约：强模型必须返回的 JSON 结构（与 data/schema/translation_sample.schema.json 对齐）
OUTPUT_CONTRACT = """
你必须也只返回一个 JSON 对象，字段如下（不要输出 JSON 以外的任何内容）：
{{
  "id": "f2cpp-{cell_slug}-{index:04d}",
  "source": "synthetic",
  "license": "synthetic",
  "fortran_dialect": "f90",
  "features": ["{feature}"],
  "input_fortran": "<完整可编译的 Fortran 程序，含 program 结尾 end program>",
  "output_cpp": "<完整可编译的 C++17 程序，含 int main()>",
  "notes": "<映射说明：每处非平凡改写的原因，特别是格式化输出与浮点精度差异>",
  "unsupported": [],
  "compile_info": {{"fortran": "gfortran -O0 -o f.out main.f90",
                    "cpp": "g++ -std=c++17 -O0 -o c.out main.cpp"}},
  "tests": [{{"name": "basic",
              "input": "<stdin 输入文本，没有输入则为空字符串>",
              "expected": "<程序运行后的 stdout 文本>",
              "rel_tolerance": 1e-9, "abs_tolerance": 1e-12,
              "comparison": "numeric_or_text"}}],
  "validation": {{"fortran_ok": false, "cpp_ok": false, "tests_ok": false, "reviewed": false}},
  "split": "train"
}}
注意：expected 必须是 Fortran 程序的"真实"输出 —— 我们会实际编译运行来核对，
编不过或输出对不上的样本会被丢弃，不要编造 expected。
"""


def build_prompt(cell: str, index: int) -> str:
    """组装单条合成 prompt。难度用'代码规模+特性组合数'控制。"""
    spec = SYNTAX_CELLS[cell]
    difficulty = cell.split("/")[1]
    size_hint = {
        "easy":   "程序总行数 15~30 行，只涉及本格语法点",
        "medium": "程序总行数 30~60 行，可组合 1~2 个其他基础语法点",
        "hard":   "程序总行数 60~120 行，可组合多个语法点，核心必须是本格主题",
    }[difficulty]
    return f"""你是 Fortran→C++17 翻译语料的构造器。

任务：编写一对严格等价的 Fortran 程序和它的人工质量 C++17 翻译。
主题：{spec['topic']}（{difficulty} 难度，{size_hint}）。

Fortran 侧要求：{spec['fortran_hint']}
C++ 侧要求：{spec['cpp_hint']}

两个程序必须读取相同的 stdin 输入并产生数值上等价的 stdout 输出。
{OUTPUT_CONTRACT}"""


def call_api(prompt: str, api_key: str, model: str = "kimi-k2.5") -> dict:
    """调用强模型 API。temperature=0.7：同一格要造多条不重复样本，温度太低会自我复制。"""
    import urllib.request

    req = urllib.request.Request(
        "https://api.moonshot.cn/v1/chat/completions",  # 换 OpenAI/DeepSeek 改这一行
        data=json.dumps({
            "model": model,
            "messages": [{"role": "user", "content": prompt}],
            "temperature": 0.7,
            "response_format": {"type": "json_object"},
        }).encode(),
        headers={"Authorization": f"Bearer {api_key}"},
    )
    with urllib.request.urlopen(req, timeout=120) as resp:
        payload = json.loads(resp.read())
    return json.loads(payload["choices"][0]["message"]["content"])


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("--cell", help="语法点格，如 array/easy；与 --all-cells 二选一")
    parser.add_argument("--all-cells", action="store_true")
    parser.add_argument("--count", type=int, default=5, help="单格条数；试跑用小值保护预算")
    parser.add_argument("--seed", type=int, default=42)
    parser.add_argument("--out-dir", default="data/raw/synthetic")
    args = parser.parse_args()

    api_key = os.environ["SYNTH_API_KEY"]  # 不设直接报错，避免误用

    cells = list(SYNTAX_CELLS) if args.all_cells else [args.cell]
    out_dir = Path(args.out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)

    for cell in cells:
        slug = cell.replace("/", "_")
        for i in range(args.count):
            prompt = build_prompt(cell, index=i)
            try:
                sample = call_api(prompt, api_key)
            except Exception as exc:  # 网络/限流：记录后跳过，不中断整批
                print(f"[SKIP] {cell} #{i}: {exc}")
                time.sleep(5)  # 简单退避，尊重限流
                continue
            # 一条一个文件；validation 全 false 是刻意的：只能由第 2 步实测回填
            (out_dir / f"{slug}_{i:04d}.json").write_text(
                json.dumps(sample, ensure_ascii=False, indent=2), encoding="utf-8")
            print(f"[OK] {cell} #{i} -> {slug}_{i:04d}.json")
            time.sleep(1)  # 温和限速


if __name__ == "__main__":
    main()
```

**[R 结论]** 试跑阶段每格 5 条（约 30 条）即可，先别放量——用通过率决定是否调 prompt，保护 API 预算。

## 第 2 步 · 双向编译验证（核心质量门）

**[S 背景]** 数据规范红线：没过双端编译运行验证的样本不得进训练集。
**[T 目的]** 每条样本：编译运行 Fortran 侧、编译运行 C++ 侧、输出按容差对比，三项全过才置 `validation` 并移入 `data/processed/`。
**[A 操作]** 阳性对照先行——用已知通过的种子样本验脚本正确性：

```bash
python scripts/verify_dual_compile.py examples/seed/001_sum_double/metadata.json            # 或加 --docker
python scripts/verify_dual_compile.py data/raw/synthetic --stats data/processed/verify_stats.json
```

### 示例：`scripts/verify_dual_compile.py`

```python
"""
verify_dual_compile.py — 双端编译运行验证（数据质量门）

职责边界：
- 本脚本只做"实测"：编译、运行、比输出、回填 validation —— 唯一被允许把
  fortran_ok/cpp_ok/tests_ok 置 true 的脚本。
- validate_dataset.py 只做静态 schema 校验。顺序不可颠倒：先静态（秒级）再实测。
- 每条样本在独立临时目录编译，避免文件名冲突和交叉污染。
"""

from __future__ import annotations

import argparse
import json
import subprocess
import sys
import tempfile
from pathlib import Path

COMPILE_TIMEOUT = 60    # 正常编译 <10s，60s 暴露病态代码
RUN_TIMEOUT = 10        # 防合成出死循环样本卡死流水线
DEFAULT_RTOL = 1e-9     # 与数据规范 tests 默认值一致；样本自带容差时以样本为准
DEFAULT_ATOL = 1e-12


def run(cmd: list[str], cwd: Path, timeout: int) -> subprocess.CompletedProcess:
    """统一执行入口：限时、捕获输出；超时返回码 124（与 GNU timeout 约定一致）。"""
    try:
        return subprocess.run(
            cmd, cwd=cwd, timeout=timeout, capture_output=True, text=True,
            # 精简环境变量：防御合成代码里夹带的意外行为
            env={"PATH": "/usr/bin:/bin", "HOME": str(cwd)},
        )
    except subprocess.TimeoutExpired:
        return subprocess.CompletedProcess(cmd, returncode=124, stdout="", stderr="TIMEOUT")


def extract_numbers(text: str) -> list[float]:
    """提取输出中的浮点序列用于数值比较。

    设计说明：Fortran F12.6 类格式化输出是'文本协议'，逐字符比较对浮点重排
    太敏感（编译器优化可能改变运算顺序）。策略：按数值序列对齐比较。
    """
    import re
    return [float(x) for x in re.findall(r"[-+]?\d+\.?\d*(?:[eE][-+]?\d+)?", text)]


def compare_output(actual: str, expected: str, rtol: float, atol: float) -> bool:
    """numeric_or_text：先试数值容差，失败退回逐行文本比较（去行尾空白）。"""
    a_nums, e_nums = extract_numbers(actual), extract_numbers(expected)
    if len(a_nums) == len(e_nums) and len(a_nums) > 0:
        return all(abs(a - e) <= max(rtol * max(abs(a), abs(e)), atol)
                   for a, e in zip(a_nums, e_nums))
    a_lines = [ln.rstrip() for ln in actual.strip().splitlines()]
    e_lines = [ln.rstrip() for ln in expected.strip().splitlines()]
    return a_lines == e_lines


def verify_one(sample: dict, workdir: Path, docker: bool) -> dict:
    """验证单条样本，返回 validation 对象。绝不抛异常 —— 验证器必须 robust。"""
    val = {"fortran_ok": False, "cpp_ok": False, "tests_ok": False, "reviewed": False}
    (workdir / "main.f90").write_text(sample["input_fortran"], encoding="utf-8")
    (workdir / "main.cpp").write_text(sample["output_cpp"], encoding="utf-8")

    # Docker 模式：gcc:13 自带 gfortran+g++；断网+只读根文件系统+挂载当前目录，
    # 与 Agent 沙箱四重限制同源（不信任任何生成代码）
    def docker_wrap(inner: list[str], timeout: int) -> list[str]:
        return ["docker", "run", "--rm", "--network", "none",
                "-v", f"{workdir}:/io", "-w", "/io", "gcc:13",
                "timeout", str(timeout), *inner]

    # --- 第一关：Fortran 参考实现必须先立住 ---
    f_cmd = ["gfortran", "-O0", "-o", "f.out", "main.f90"]
    f_compile = run(docker_wrap(f_cmd, COMPILE_TIMEOUT) if docker else f_cmd,
                    workdir, COMPILE_TIMEOUT + 30)
    if f_compile.returncode != 0:
        return val  # 参考实现都编不过：合成质量差的直接证据

    # --- 第二关：C++ 侧编译（最常见失败模式：缺头文件/类型错误） ---
    c_cmd = ["g++", "-std=c++17", "-O0", "-o", "c.out", "main.cpp"]
    c_compile = run(docker_wrap(c_cmd, COMPILE_TIMEOUT) if docker else c_cmd,
                    workdir, COMPILE_TIMEOUT + 30)
    val["fortran_ok"] = True
    if c_compile.returncode != 0:
        return val

    # --- 第三关：每个测试用例双端同 stdin、比 stdout（双保险） ---
    tests_ok = True
    for test in sample.get("tests", []):
        stdin_data = test.get("input", "")
        expected = test.get("expected", "")
        rtol = test.get("rel_tolerance", DEFAULT_RTOL)
        atol = test.get("abs_tolerance", DEFAULT_ATOL)

        f_run = run(["./f.out"], workdir, RUN_TIMEOUT)
        c_run = run(["./c.out"], workdir, RUN_TIMEOUT)
        if f_run.returncode != 0 or c_run.returncode != 0:
            tests_ok = False
            break
        # 先比 C++ vs expected，再比双端一致性 —— 两个方向都要过
        if not compare_output(c_run.stdout, expected, rtol, atol):
            tests_ok = False
            break
        if not compare_output(f_run.stdout, c_run.stdout, rtol, atol):
            tests_ok = False
            break

    val["cpp_ok"] = True
    val["tests_ok"] = tests_ok
    return val


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("inputs", nargs="+", help="样本 JSON 文件或目录")
    parser.add_argument("--processed-dir", default="data/processed")
    parser.add_argument("--rejected-dir", default="data/raw/rejected")  # 被拒样本不删：第 3 步修复对原料
    parser.add_argument("--docker", action="store_true")
    parser.add_argument("--stats", default="data/processed/verify_stats.json")
    args = parser.parse_args()

    files: list[Path] = []
    for item in args.inputs:
        p = Path(item)
        files.extend(sorted(p.glob("*.json")) if p.is_dir() else [p])

    stats: dict[str, dict[str, int]] = {}  # 按语法点格统计通过率，暴露哪格合成质量差
    passed = rejected = 0
    for f in files:
        sample = json.loads(f.read_text(encoding="utf-8"))
        with tempfile.TemporaryDirectory() as tmp:
            val = verify_one(sample, Path(tmp), docker=args.docker)
        sample["validation"] = val

        # 文件名约定（合成脚本产出）→ 语法点格：array_easy_0003 -> array/easy
        # 两个脚本的唯一耦合点就是这个命名约定，改动需谨慎
        cell = f.stem.rsplit("_", 1)[0].replace("_", "/", 1)
        bucket = stats.setdefault(cell, {"total": 0, "passed": 0})
        bucket["total"] += 1

        ok = val["fortran_ok"] and val["cpp_ok"] and val["tests_ok"]
        out = Path(args.processed_dir if ok else args.rejected_dir) / f.name
        passed, rejected = (passed + 1, rejected) if ok else (passed, rejected + 1)
        if ok:
            bucket["passed"] += 1
        out.parent.mkdir(parents=True, exist_ok=True)
        out.write_text(json.dumps(sample, ensure_ascii=False, indent=2), encoding="utf-8")
        print(f"{'PASS' if ok else 'REJ '} {f.name} {val}")

    Path(args.stats).write_text(json.dumps(stats, indent=2), encoding="utf-8")
    print(f"\n== 总计 {passed} 通过 / {rejected} 被拒 ==")
    for cell, s in sorted(stats.items()):
        print(f"  {cell:20s} {s['passed']}/{s['total']}")


if __name__ == "__main__":
    sys.exit(main())
```

**[R 结论]** 回填三个数：①种子阳性对照 PASS（脚本正确性）；②整批通过率（预期 40–70%，低则调合成 prompt）；③`verify_stats.json` 哪格最差（定向修 prompt 的依据）。

## 第 3 步 · 修复对生成（设计 + 关键片段）

**[S 背景]** ADR-0002：修复对占 30%。第 2 步的自然失败太少且类型单一，需规则化造错覆盖 g++ 报错类型。
**[T 目的]** 产出"错误 C++ + g++ 真实 stderr → 修复版"三元组。验收：错误类别覆盖 ≥5 类。

### 设计思路

对已 PASS 样本施加**变异算子**，每类算子对应一类真实编译错误：

```
变异算子
├── drop_include      删 #include 行            → 缺头文件类
├── type_mismatch     double 初始化塞字符串     → 类型不匹配类
├── undeclared        变量改名 typo_xxx         → 未声明标识符类
├── missing_return    删 return                 → 控制流到达末尾类
├── link_error        声明不实现                 → undefined reference 类
└── wrong_format      setprecision ±1           → 数值偏差类（编过但测试挂，训练 diagnose 的"数值偏差"分支）
```

`wrong_format` 尤其重要——它训练 diagnose 节点里最难自动修的"数值偏差"类别。

### 关键片段：`scripts/mutate_for_repair.py`

```python
"""
mutate_for_repair.py — 从通过验证的样本批量生成"修复训练对"

设计要点：
1. 变异源只用第 2 步 PASS 的样本 —— "修复目标"必须是正确代码，模型学的是
   "从错误到正确"，不是"一种错误到另一种错误"。
2. 错误文本必须来自 g++ 真实 stderr，不伪造 —— 否则模型学到的是"匹配错误
   模板"而不是"读错误信息"。
3. 每条记录变异算子名，支持按错误类别统计和配比。

产出（ShareGPT 对话，对齐 convert_to_llamafactory.py 输入）：
  user:      [Fortran 源码] + [错误 C++ 代码] + [编译命令] + [stderr 截断]
  assistant: [修复后的正确 C++] + [修复说明]
"""

MUTATORS: dict[str, str] = {
    # 算子名: 期望的错误类别
    "drop_include":   "缺头文件",
    "undeclared":     "未声明标识符",
    "type_mismatch":  "类型不匹配",
    "missing_return": "控制流到达末尾",
    "link_error":     "undefined reference",
    "wrong_format":   "数值偏差(编译通过,测试失败)",
}

def apply_mutation(cpp_code: str, operator: str) -> str | None:
    """施加一个变异算子；算子不适用（如没有 return 可删）返回 None 并跳过，
    不换个源强造 —— 保证错误分布真实。"""
    import re
    if operator == "drop_include":
        m = re.search(r"^#include.*$", cpp_code, re.M)
        return cpp_code[:m.start()] + cpp_code[m.end():] if m else None
    if operator == "undeclared":
        m = re.search(r"\b(double|int|auto)\s+(\w+)", cpp_code)
        return cpp_code.replace(m.group(2), "typo_" + m.group(2), 1) if m else None
    raise ValueError(operator)  # 其余算子同理，每类 3~8 行正则

# 主流程：
# for sample in data/processed/*.json:
#     for op in MUTATORS:
#         bad_cpp = apply_mutation(sample.output_cpp, op)
#         if bad_cpp is None: continue
#         result = compile(bad_cpp)                    # 复用 verify 的 run()
#         if op == "wrong_format":
#             # 数值偏差类要求"编过但测试挂"，单独跑测试确认确实挂才收
#             if not runs_but_fails_tests(bad_cpp, sample.tests): continue
#             stderr = "<数值偏差：双端输出在容差外>"      # 此类没有编译错误文本
#         else:
#             if result.returncode == 0: continue        # 没造出错误就丢弃
#             stderr = result.stderr[-2000:]             # 截断防上下文膨胀（方案 3.4）
#         emit_repair_pair(sample.input_fortran, bad_cpp, stderr,
#                          fixed=sample.output_cpp, op=op)
```

**[R 结论]** 修复对数量 ≈ PASS 样本 × 可用算子数，自动接近 30% 配比。
