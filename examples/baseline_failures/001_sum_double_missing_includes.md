# 基线失败案例 001：sum_double 缺少头文件与格式宽度

## 目的

记录本地 `qwen3.5:2b` 在第一个种子样本上的真实输出，作为后续 LoRA 和 Agent 修复闭环的对照。

## 输入

种子样本：

`examples/seed/001_sum_double/`

Fortran 行为：

- 读取 `n`；
- 读取 `n` 个 `real(8)`；
- 求和；
- 用 `F12.6` 输出。

## 模型输出摘要

模型返回了合法 JSON，且 `confidence` 为 `high`，但生成的 C++ 代码：

- 使用了 `std::cin` / `std::cout`，但没有包含 `<iostream>`；
- 使用了 `std::fixed` / `std::setprecision`，但没有包含 `<iomanip>`；
- 没有保留 `F12.6` 的字段宽度；
- `notes` 声称“匹配 F12.6”，与实际代码不一致。

## 失败分类

| 维度 | 结果 |
|---|---|
| JSON 解析 | 通过 |
| C++ 编译 | 预计失败：缺少头文件 |
| 输出格式 | 不满足 `F12.6` |
| 数值逻辑 | 求和逻辑基本正确 |
| 置信度校准 | 失败：模型给出 `high`，但代码不可编译 |

## 结论

这条案例说明：

1. 微调前的小模型可以生成“看起来合理”的代码；
2. JSON 结构稳定不等于代码正确；
3. 编译器和测试必须进入闭环；
4. 后续修复提示词应优先加入“包含必要头文件、保留格式化输出、不能用注释替代代码”。
